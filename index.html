Comment fonctionne la surveillance

  1. Tu déclares ici le script à surveiller. Cela ajoute quelques lignes dans monitoring.json, la liste de référence.
  2. Le script, sur le Mac, signale qu'il a tourné en appelant heartbeat.py avec son identifiant. Il dépose ainsi son horodatage dans le dépôt.
  3. Chaque matin vers 6 h, un contrôle automatique compare l'heure du dernier signal au seuil que tu fixes. Si le script est muet, tu reçois un mail le nommant.

Ajouter un script

Le nom technique, celui que le script passera à heartbeat.py. Lettres minuscules, chiffres et tirets uniquement — ni espace, ni accent, ni majuscule.
Le nom qui apparaîtra dans l'alerte et dans la liste. Écris-le comme tu le dirais : c'est ce que tu liras dans le mail, un matin, à moitié réveillé.
« Battement de cœur » convient à presque tout : le script appelle heartbeat.py et son fichier de suivi est créé tout seul. « Journal existant » sert quand le script écrit déjà lui-même un fichier daté dans le dépôt, comme la box avec activity.json.
Chemin du fichier dans le dépôt, tel qu'il apparaît sur GitHub.
Au-delà de ce silence, le script est considéré à l'arrêt. Prends un peu de marge sur sa fréquence réelle : 26 h pour un script quotidien, 2 h pour un script horaire. Trop serré, tu recevras de fausses alertes ; trop large, tu découvriras la panne tard.
Décoche pour déclarer le script sans le surveiller encore — utile le temps de le mettre en place.
